# سَنَد | SANAD

منصة مصرية رقمية تساعد المواطنين على فهم احتياجاتهم والوصول إلى الخدمات والمعلومات والفرص من مصادر الجهات الرسمية.

**الشعار:** سَنَد.. نوصلك للي تحتاجه.

## ما يتوفر في المشروع

- سبعة أقسام: الخدمات الحكومية، التعليم، المساعدات والدعم، الإتاحة لذوي الإعاقة وكبار السن، الفرص والمبادرات، دعم المشروعات الصغيرة، والخدمات البنكية.
- بحث عربي يراعي اختلافات الكتابة والتشكيل، ويبحث في بيانات الخدمات المنشورة.
- تصفية الخدمات حسب القسم والجهة.
- صفحات تفاصيل تعرض المعلومات المتاحة عن الخدمة، والجهة المسؤولة، والشروط والمستندات والخطوات والمصادر.
- حسابات بالبريد الإلكتروني وكلمة مرور، وجلسات HttpOnly، ومزامنة المفضلة مع الحساب.
- مفضلة محلية للزوار ومشاركة روابط الخدمات.
- إعدادات حجم الخط والوضع الداكن.
- تخزين مؤقت لبيانات الخدمات لتصفح البيانات التي سبق تحميلها عند انقطاع الإنترنت.
- لوحة إدارة لإضافة الخدمات وتعديلها ومراجعتها ونشرها أو إلغاء نشرها.
- استقبال بلاغات عن المعلومات الخاطئة والروابط المعطلة.
- التصفح والبحث لا يتطلبان إنشاء حساب.

بعض التفاصيل مثل الرسوم والمواعيد والأهلية قد تختلف بحسب الحالة أو تحديثات الجهة المختصة؛ لذلك يجب الرجوع إلى المصدر الرسمي قبل اتخاذ إجراء.

## التقنيات المستخدمة

- **الواجهة:** React 18، Vite 6، React Router 7، JavaScript، CSS، Lucide React.
- **الخلفية:** Python 3.12، FastAPI، Uvicorn، Pydantic، SQLAlchemy.
- **قاعدة بيانات الإنتاج:** Neon PostgreSQL، عبر psycopg 3.
- **تطبيق Windows:** Tauri 2 وRust.
- **تطبيق Android:** Capacitor 8.
- **النشر وإدارة الإصدارات:** Vercel، Git، GitHub، وGitHub Actions.

## تنظيم المشروع

- `src/pages/`: صفحات التطبيق ومساراته.
- `src/components/`: مكونات الواجهة القابلة لإعادة الاستخدام.
- `src/utils/`: وظائف مساعدة، مثل جلب الخدمات وإدارة المفضلة.
- `backend/main.py`: مسارات API.
- `backend/models.py` و`backend/schemas.py`: نماذج البيانات والتحقق من الطلبات.
- `backend/tests/`: اختبارات وحدات للباك إند.
- `docs/`: توثيق المشروع ومراجعة مصادر الخدمات.

## تشغيل الواجهة محليًا

من مجلد المشروع:

```powershell
npm.cmd ci
npm.cmd run dev
```

## تشغيل الباك إند محليًا

من مجلد المشروع:

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn main:app --reload
```

توثيق API المحلي: http://127.0.0.1:8000/docs

## متغيرات البيئة

- الواجهة: اضبط `VITE_API_URL` في `.env.local`. القيمة الافتراضية في `src/api.js` تشير إلى API المنشور.
- الباك إند: اضبط `DATABASE_URL` على رابط Neon PostgreSQL في بيئة الإنتاج.
- اضبط `SANAD_ADMIN_TOKEN` و`SANAD_ALLOWED_ORIGINS` في إعدادات استضافة الباك إند، ولا تضع الأسرار في الواجهة أو في GitHub.
- في بيئة الإنتاج المنفصلة النطاقات، استخدم HTTPS واضبط إعدادات Cookie بما يتوافق مع النطاقات المسموح بها.
- عند التشغيل المحلي دون `DATABASE_URL`، يستخدم إعداد التطوير قاعدة SQLite محلية فقط؛ هذا ليس إعداد قاعدة بيانات الإنتاج.

تفاصيل إعدادات النشر موجودة في `docs/backend-deployment.md`.

## لوحة الإدارة

المسار: `/admin` على الموقع. يجب ضبط `SANAD_ADMIN_TOKEN` في بيئة الباك إند قبل استخدامها. تعود الخدمة المعدلة إلى حالة المسودة حتى تتم مراجعتها مجددًا. لا يسمح النظام بنشر خدمة دون استكمال الحقول الأساسية ورابط مصدر HTTPS.

## البيانات والمصادر

يحتفظ سجل الخدمة برابط المصدر وتاريخ المراجعة. وجود رابط رسمي وحده لا يثبت صحة كل التفاصيل؛ يجب أن يدعم المصدر المعلومات المنشورة عن الخدمة. لا تُعرض الرسوم أو المواعيد أو الشروط غير المؤكدة على أنها حقائق ثابتة.

## الاختبارات

من جذر المشروع:

```powershell
npm.cmd run build
cd backend
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

تشمل اختبارات الباك إند التحقق من قواعد نشر الخدمة، وروابط المصادر، وأدوات المصادقة والجلسات. نجاح اختبارات الوحدات لا يعني أن جميع الوظائف أو الأجهزة خضعت لاختبار شامل.

## مبادئ سَنَد

- التصفح والبحث دون اشتراط إنشاء حساب.
- ربط المعلومات بمصادرها الرسمية.
- عدم افتراض الرسوم أو الشروط أو المواعيد غير المؤكدة.
- إعادة الخدمة المعدلة إلى المسودات حتى تتم مراجعتها.
- واجهة عربية باتجاه RTL مع مراعاة سهولة الاستخدام.
